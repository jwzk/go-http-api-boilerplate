# Generate Mocks Skill

This skill instructs the AI on the correct process to generate or update interface mocks within the Go HTTP API project. Mocks are critical for writing isolated unit tests, particularly when testing usecases and HTTP handlers.

## Workflow

1.  **Check Configuration:** Ensure the `.mockery.yml` file is present in the root directory. This configuration dictates where and how mocks are generated (typically they go to a `mocks/` directory near the interfaces they implement).
2.  **Ensure Interfaces exist:** Ensure the interfaces you want to mock exist inside the `internal/domain/port` directory and are fully defined.
3.  **Run Mockery:** Execute the standard Go generation command or run the `mockery` binary directly in the project root. Since `mockery` is often an external dependency:
    ```bash
    go run github.com/vektra/mockery/v2@latest
    ```
4.  **Verify Output:** Confirm that the mock files have been created or updated successfully based on the output of the command.
5.  **Utilize in Tests:** Import the generated mock packages in your test files.
    *   Initialize mocks (e.g., `mockDAO := mocks.NewBookDAO(t)`).
    *   Set up expectations (e.g., `mockDAO.On("Save", mock.Anything, mock.Anything).Return(expectedBook, nil)`).
    *   Inject the mock into the component being tested.

## Constraints
- Do not manually edit files generated by mockery, as your changes will be overwritten on the next run.
- Do not check in mock configurations that deviate from the established `.mockery.yml` unless explicitly instructed by the user.
